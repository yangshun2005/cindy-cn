# Cindy 设计系统

> 传承说明：此视觉语言最初源自一个外部极简主义参考（2025年）。此后已演变为 Cindy 自己的系统——新的设计决策不再参考任何外部网站或产品。

## 1. 视觉主题与氛围

Cindy 的界面是将激进极简主义应用于 AI 代理工作台——一个安静、近乎单色的画布，用户的 content 和代理的输出是唯一需要关注的元素。设计理念与产品本身相呼应：剥离一切不必要的东西，直到只剩下必不可少的工具。这相当于数字领域的 Dieter Rams 设计——每个像素都物有所值，而装饰的缺席本身就是设计。

默认主题几乎完全处于灰度中。彩色被保留给一小部分明确授权的语义信号（状态、差异、焦点——见 §2）；其他一切都是介于近黑和近白之间的色调。长时间的工作会话保持平静，而颜色一旦出现就必定有意义。

这个系统的独特之处在于将单一几何无衬线字体（Inter）与以胶囊形状为主的几何形态（交互元素上使用 9999px 圆角）相结合。清晰的字体 + 圆角按钮 + 圆角容器创造了一种连贯的“柔和语言”，使面向开发者的工具显得平易近人、友好，而不是令人生畏。这是带有温度的极简主义——不是冰冷的瑞士网格极简主义，而是边缘被真正柔化的那种。

**关键特征：**

- 近乎单色的默认主题；彩色仅通过授权的语义集（§2）使用，且始终通过 token 消费（§10）
- Inter 作为唯一的无衬线字体家族，同时承载展示标题和正文
- 紧凑的圆角系统：8px（内部控件）/ 12px（容器）/ 9999px（胶囊）——只有三个值，没有其他
- 基础语言中零阴影——深度来自背景色变化和 1px 边框（窄 token 门控例外见 §10）
- 所有交互元素（按钮、标签页、输入框、标签）均采用胶囊形状
- 工作 UI 中没有吉祥物或装饰性插图——品牌图像仅出现在授权的品牌表面上（见 §15.7 / §16）
- 极端的内容克制——每个表面呈现一个清晰的想法

## 2. 调色板与角色

> **多主题说明**：本节中的值是具体的 **默认浅色 / 默认深色**（基础主题）调色板，作为视觉规范参考样本。在运行时，**每种颜色都通过 token 消费**（见 §10 主题系统与 Token 参考），因此相同的组件在其他主题（Eclipse / One Dark Pro / Monokai Pro，……）下会自动渲染每个主题自己的颜色。**实现组件时，始终编写 token，绝不使用 hex** —— 规则见 §10。

### 主要文本

- **纯黑**（`#000000`）：主要标题、主要链接以及浅色模式下最深的文本。唯一需要关注的“颜色”。**绝不用作背景**——仅保留给文本和图标。
- **近黑**（`#262626`）：浅色表面上的按钮文本，次要标题字重。

### 图层系统（浅色与深色）

界面由三层图层系统构建，对称地应用于两种模式——**Surface** 作为基础，**Card** 作为抬高层，**Board** 作为发丝线分隔线。这是每种模式下每个页面的基础。

| 角色 | 浅色模式 | 深色模式 | 用途 |
|---|---|---|---|
| **Surface** | `#f8f8f6` | `#1f1f1e` | 主要页面背景——每个页面都从这里开始。在全窗口应用布局中，这是单一的平面背景。在居中卡片布局中，这是卡片下方的页面。 |
| **Card** | `#ffffff` | `#2c2c2a` | 位于 Surface 之上的抬高层——登录卡片、模态框、面板、凸起的容器，以及任何需要视觉上从页面浮起的元素。 |
| **Board** | `#d7d7d4` | `#3c3c3a` | 发丝线分隔线颜色——区域之间的 1px 边框、卡片轮廓，以及同一图层内的任何分隔线。 |

**图层规则——平面与抬升：**

- **全窗口应用**（例如主工作区、聊天界面、仪表板）：使用 **Surface** 作为整个窗口的单一平面背景——页面结构级别不使用 Card 层。区域边界（侧边栏、工具栏、内容区域）用 1px **Board** 分隔线绘制，绝不用背景色变化。
- **居中卡片布局**（例如登录、模态框、空白页面上的空状态卡片）：使用 **Surface** 作为页面背景，**Card** 作为抬升的卡片。Surface 和 Card 之间的颜色差异使卡片呈现“抬升”感——无需阴影。卡片轮廓用 **Board** 绘制。

> **重要——元素级与页面级：** 全窗口布局中的“平面 Surface”规则仅适用于**整体页面结构**，不适用于单个小部件。全窗口布局*内部*的抬升小部件——输入框、聊天输入框、凸起的卡片、模态遮罩、面板弹窗——仍根据其组件规则使用 **Card** 颜色（见第 4 节）。全窗口聊天界面可以同时拥有平面 Surface 页面*和* Card 颜色的聊天输入框；这是两个不同的作用域。“Surface 平面”意味着“不要将页面拆分为 Page+Card 层”，而不是“页面上的每个元素都必须是 Surface 颜色”。

### Chip 与按钮中性色

小型交互式 chip（按钮背景、标签胶囊、头像填充、选中导航胶囊）位于图层系统之外——它们是前景元素，不是背景层。

- **浅灰色**（`#e5e5e5`）：浅色模式下的 chip/按钮背景——用于按下状态、填充胶囊、标签背景和头像填充的主力中性色。
- **深色 Chip**（`#3c3c3a`，token `--surface-chip`）：深色模式下的主要 chip/按钮背景——比 Card 或 Surface 上下文高一级。
- **深色 Chip Alt**（`#2c2c2a`，token `--surface-chip-alt`）：折叠到深色 Card 值的变体——用于 chip 直接位于 Surface 上且只需要 Card 级抬升的情况。如有疑问，使用 `--surface-chip`；两个槽位见 §10。

> ~~**边框浅色**（`#d4d4d4`）~~ — 已弃用（2026-06，G2）。曾被称为“白色按钮边框颜色”，但从未有真实组件使用过它（仅在实验视图中出现过裸硬编码）。白色胶囊次要边框统一使用 **Board**（`--border-default` `#d7d7d4`）。

### 中性色与文本

- **Stone**（`#737373`）：次要正文文本、页脚链接和弱化内容。主要的“柔和”色调。
- **中灰色**（`#525252`）：强调的次要文本，比 Stone 略深。
- **Silver**（`#a3a3a3`）：三级文本和深度弱化的元数据。**绝不用作占位符**——过于突出，会被误读为已填写的内容（见 §4 输入框；G3 勘误已归档于 [`design-decision-log.md`](./design-decision-log.md)；占位符使用 `--text-placeholder` `#c4c4c4`）。

> ~~**按钮文本深色**（`#404040`）~~ — 已弃用（2026-06，G1）。曾被称为“白色表面按钮文本颜色”，但从未有真实按钮使用过它（仅在实验视图中出现过裸硬编码）。白色胶囊次要文本统一使用 **近黑**（`--text-primary` `#262626`）。

### 语义与强调色

灰度规则近乎绝对。以下是系统中**仅有的**授权非灰色颜色——每种都严格限定在特定表面上。不得在未先在此记录的情况下引入新的语义颜色。

- **焦点蓝**（`#417CDD` 50%；tokens `--focus-ring` / `--focus-ring-soft`）：键盘无障碍焦点环，定稿于 2026-07-17（取代 Tailwind 默认的 `#3b82f6`）。在正常交互流程中不可见。
- **思考 / 警告橙**（`#EA6B17`，定稿于 2026-07-17，取代冻结的 `#FF6600`）：共享的警告强调色家族，两种模式相同。仅限授权消费者——ChatView 运行状态栏（sparkles 图标 + 状态文本，例如 `Spelunking...`，无背景填充）、侧边栏中的运行状态呼吸图标、协作模式菜单行的 ON 状态、计划批准图标、完全访问权限高亮、设置集成警告，以及工作流代理状态条中的运行单元格（后台任务面板详情和工作流聊天卡片中的 8×8px 填充方块，注册于 2026-07-28——运行状态语义，与侧边栏呼吸图标同族；完成/失败/排队单元格保持各自的语义 token：`--card-status-done` / `--error-fg` / `--surface-chip`），以及侧边栏任务信息 PR 未解决角点（注册于 2026-08-17——与会话头未解决计数相同的 `--status-bar-accent`；静态，无呼吸）（完整 token 列表见 §10 豁免表和 §15：`--warning-accent` 及其跟随 token）。不引入新 token 的消费者——直接读取 `--warning-accent` 或现有跟随 token 的消费者，如该条——仅由此列表注册；需要新 token 的消费者必须先在 §10 豁免表中注册。

### 渐变系统

- **核心 UI 中无渐变。** Cindy 不使用渐变；视觉分离来自纯色块和单像素边框。这是一个深思熟虑的、几乎是哲学性的设计选择。（登录画布也按规定是纯色的——见 §16.5。）
- **会话加载字标扫光——窄功能例外（桌面端批准于 2026-08-10）。** `BrandLoadingMark` 可以在会话的消息树被延迟时，在官方浅色/深色字标内部使用一个中性的 `transparent → --text-primary → transparent` 渐变，仅作为遮罩裁剪的高光。它是一个加载进度信号，不是背景、分隔线、填充或可复用的表面处理。它只能在 200ms 延迟显示阈值之后出现，一旦消息树挂载就消失，并且不得泄漏到消息、卡片、对话框、侧边栏或静态品牌中。完整的动效和品牌表面约束在 §14.4 和 §15.7 中注册。

## 3. 字体排版规则

### 字体家族

- **展示 / 正文 / UI**：`Inter`，回退字体：`system-ui, -apple-system, "Segoe UI", sans-serif`
- **等宽字体**：`JetBrains Mono`，回退字体：`ui-monospace, SFMono-Regular, Menlo, Monaco, Consolas, monospace`

*注意：整个界面使用单一无衬线字体——Inter——同时用于展示标题和正文。选择 Inter 是因为 (a) 其中性、几何化的特征不会喧宾夺主，(b) 在小尺寸下具有出色的易读性，以及 (c) 在 Web 和设计工具中广泛可用。单一字体保持层级清晰——分离来自大小和字重，而不是字体对比。*

| 章节标题 | Inter | 36px (2.25rem) | 500 | 1.11 (紧凑)
