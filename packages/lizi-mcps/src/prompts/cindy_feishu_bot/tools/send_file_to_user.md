通过已配置的飞书 / Lark 机器人，将本地文件推送给当前用户（机器人归属人）。`chatId` 由会话上下文自动注入，**不要也不能**作为参数传入 —— 你只需关心“发什么”。

**接收人语义**（与 `send_message_to_user` 一致）：优先发送到当前会话归属的 IM 聊天（在飞书或 Lark 中私聊机器人触发的会话）；若当前不是该 IM 会话（桌面端聊天中，代理被要求“把这个截图 / 报告发飞书或 Lark 给我”），则自动回落到机器人首次被私聊时 TOFU 记录的归属人。两条路径最终都会发送到用户私聊机器人的对话中，不会发送给其他任何人。

用途：

- **跨会话文件推送**：用户在桌面端说“把这份文档 / 这张图发飞书或 Lark 给我” —— 使用此工具，文件会立即出现在对应 IM 的私聊中。
- **IM 会话内直接发送**：用户让你“出张图发我看看”、“把日志文件传过来” —— 任何需要将磁盘上的文件本体发送到用户手机/PC 客户端的场景。
- **不要**使用此工具发送卡片正文中的内联说明，正文使用流式输出即可；此工具用于发送独立的文件/图片消息（用户会看到“📎 文件名”或图片预览，可直接下载/转发）。
- 当用户未明确表达“发飞书 / Lark 给我”或类似意图时，不要主动推送文件。

参数：

- `absPath`（必填）：本地绝对路径。Windows 可使用正斜杠或反斜杠；Unix 使用 `/...`。
- `displayName`（可选）：发送给用户时显示的文件名，默认使用 `path.basename(absPath)`。

行为：

- 图片（`.png .jpg .jpeg .gif .webp .bmp`）且 ≤ 10MB → 自动以 `msg_type:'image'` 发送，用户可在聊天中直接预览，无需下载。
- 其他文件或超过图片大小上限的图片 → 以 `msg_type:'file'` 发送，客户端会显示文件名和下载按钮。
- 单文件硬上限为 30MB（平台侧限制），超出后返回 `FILE_TOO_LARGE`，通过 `errorCode` 让你知道是规格问题而非网络问题。

错误码：

- `NO_CHAT_CONTEXT` —— 既不在飞书 / Lark 会话中，机器人也未绑定归属人（用户从未私聊过机器人）。请告知用户先在已配置的 IM 服务中私聊机器人一次完成绑定，然后重试。不要自行重试。
- `FILE_NOT_FOUND` —— `absPath` 不存在，请检查路径。
- `FILE_EMPTY` —— 0 字节文件，平台拒绝接收。
- `FILE_TOO_LARGE` —— 超过 30MB。
- `UPLOAD_FAILED` / `SEND_FAILED` —— 网络/权限/SDK 错误，返回原始错误信息。

成功时返回 `{ ok: true, sent: { absPath, displayName, kind: 'image'|'file' } }`，你可以在卡片正文中轻描淡写地提一句“已发出”即可，无需重复路径。
