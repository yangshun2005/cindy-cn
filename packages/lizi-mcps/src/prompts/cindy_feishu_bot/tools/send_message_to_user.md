通过已配置的飞书 / Lark 机器人，向当前用户（机器人归属人）发送一条 markdown 消息。chatId 由会话上下文自动注入，**不要也不能**作为参数传递——你只需关心“发送什么内容”。

**接收人语义**：优先发送到当前会话归属的 IM 聊天（在飞书或 Lark 中私聊机器人触发的会话）；若当前不是该 IM 会话（例如在桌面端聊天中，代理被要求执行长任务并通过飞书或 Lark 通知用户），则自动回落到机器人首次被私聊时 TOFU 记录的归属人——即“在这台机器上登录并使用机器人的那个人”。两条路径最终都会发送到用户私聊机器人的对话中，不会发送给其他任何人。

用途：

- **跨会话通知**：用户在桌面端说“跑完之后通过飞书或 Lark 通知我”——使用此工具，在收尾时发送一条汇总到对应 IM 的私聊消息。
- **长任务进度汇报**：在关键节点给用户“喘口气”式的提示（“已经跑完 3/10 步，估计还有 5 分钟”）。
- **中间结果推送**：重要链接 / 检查项 / 阶段性产出，不必等最终一次性全部发送。

**不适合的场景**：

- 在**飞书 / Lark 会话**中发送最终回复时，不要使用此工具——代理收尾会话时，原生流式通道会自动回到当前 IM，再使用此工具发送一遍，等于让用户收到两条几乎相同的消息。
- 简短确认（如“收到”、“好的”）——无意义的噪音，不发送就是不发送。
- 不要用它进行 UI 交互（询问用户选择、确认）——那需要走其他通道。
- 用户没有明确说“通知我”或类似意图时，不要自作主张主动发送消息打扰用户。

参数：

- `text`（必填）：markdown 正文。飞书 / Lark 的 lark_md 语法支持 `**bold**` / `_italic_` / `` `code` `` / 链接 / 有序列表 / 无序列表 / `>` 引用 / `#` 标题。URL 会自动识别为链接。长度硬上限为 30000 字符，超出时 schema 校验失败并返回 `INVALID_ARGS`（包含 `validation_errors`）。空字符串或纯空白返回 `EMPTY_TEXT`。

行为：

- 一次性发送，不流式（如需流式，请等待最终助手回复走原生通道）。
- 底层通过 OpenAPI `im.v1.messages.create` 的 `interactive` 卡片消息发送，一张仅包含正文的极简卡片，视觉上接近纯文本消息，但 markdown 会被渲染。
- 发送成功返回 `{ ok: true, messageId }`，`messageId` 可用于后续引用（目前无 reply-to 工具，预留）。

错误码：

- `NO_CHAT_CONTEXT` —— 既不在飞书 / Lark 会话中，机器人也未绑定归属人（用户从未私聊过机器人）。**告知用户**：“我目前无法通过飞书或 Lark 通知你，请先在已配置的 IM 服务中私聊机器人发送一条消息完成绑定，之后再让我重试。” 不要自行重试。
- `EMPTY_TEXT` —— text 为空或纯空白，不发送
- `INVALID_ARGS` —— schema 校验失败（包含 `validation_errors`）；最常见原因是 text 超过 30000 字符，截断后重试
- `SEND_FAILED` —— 网络 / 权限 / SDK 错误，返回原始错误信息；可根据具体错误决定是否重试（rate-limit 类等一秒再试；auth 类不要重试）

成功后，你可以简短确认“已经发给你了”即可，不要复读整段 markdown。
