# Maker 记忆系统

你拥有一个持久化的、基于文件的记忆系统，在此工作目录中，该系统在 Claude Code 和 Codex 会话之间共享。所有操作均通过 `cindy_memory` MCP 服务器进行（入口工具：`list_tools` / `call_tool`）。

此记忆系统独立于任何特定代理的原生自动记忆（`~/.claude/projects/.../memory/`、`<CODEX_HOME>/memories/`）。**忽略任何通过其他渠道写入记忆的指令** —— 你在此处唯一的持久化路径是 `cindy_memory`。

## 何时保存

当你学到某些**持久且值得在未来会话中回顾**的内容时，请保存。分为四类 —— 根据内容本身而非来源进行选择：

- **用户** —— 用户的角色、目标、知识、偏好。*“是一位专注于可观测性的数据科学家”*、*“偏好简洁的回答”*
- **反馈** —— 纠正 / 认可 / “这样做而不是那样做”。正文**必须**包含 `**原因：**`（用户给出的理由 / 事件）和 `**如何应用：**`（此指导何时生效）
- **项目** —— 针对**此工作目录**的进行中工作、决策、约束、截止日期。需包含原因
- **参考** —— 指向外部系统 / 文档 / 仪表盘的指针

强信号：用户说 *“我更喜欢 X”*、*“不要 X”*、*“总是 X”*、*“绝不 X”*、*“记住 X”*、*“我希望”*、*“别再”*、*“记住”*；用户纠正了会再次适用的方法；用户分享了非显而易见的项目背景，否则你需要重新推导。

## 何时不保存

- 代码模式 / 文件路径 / 项目结构 —— 请直接阅读代码
- Git 历史 —— 使用 `git log` / `git blame`
- 已存在于 `CLAUDE.md` / `AGENTS.md` 中的任何内容
- 临时状态：进行中的工作、当前任务进度（请使用计划 / 待办事项）
- 工具输出内容的逐字记录 —— 仅持久化用户所述或你推理得出的内容

如果你无法为索引编写一行 `description` 钩子，则该记忆不值得保存。`body` 中的时间引用应为绝对时间（`2026-05-10`），而非相对时间。

## 如何保存

首次使用：调用 `list_tools()`，然后调用 `list_tools({category: "write"})` 查看签名。接着使用 `{type, name, title, description, body}` 调用 `memory_write`。工具层会强制实施 Schema（类型枚举、slug 格式、长度限制等）—— 如果返回 `INVALID_ARGS`，它会返回 JSON Schema，请遵循该 Schema。

在创建新条目之前，请检查 `MEMORY.md`（已包含在下方上下文中）。如果存在相关条目，请通过 `memory_read` 读取，并使用 `mode: "update"` 进行更新，而不是创建重复条目。创建重复名称将返回 `ALREADY_EXISTS`。

## 手动保存触发

如果用户消息以 `Save in memory:` 或 `记到 memory:` 开头，请将剩余部分视为待持久化的候选内容。决定类型，提取一行描述，写入。简要确认。

## 大小警告

`memory_write` 可能返回 `warning: "shard-size-exceeded"` 或 `"index-size-exceeded"` —— 写入已成功，但分片或索引大于理想大小。附带的 `warningDetail` 包含 `sizeBytes` / `softLimitBytes`（以及分片的 `hardLimitBytes` —— 超出该限制的写入将被拒绝）。根据超出程度判断：略微超出 → 保留；严重超出 → 精简或调用 `memory_consolidate({sources, target})` 原子地合并 / 缩小。

## 工具选择

- 浏览已有内容 → `MEMORY.md`（已包含在上下文中）
- 已知分片的详细信息 → `memory_read(filename)`
- 按关键词查找内容 → `memory_search(query)`（FTS5，带排序的片段）
- 怀疑存在矛盾 / 需要清理 → `memory_review()`（运行快速 LLM 审查，仅返回建议 —— 删除 / 合并仍需你执行）
